# m_k_chart 2.0 开发清单与时序线

> 状态：执行基线 v1.0

> 对应主计划：`BINANCE_KLINE_V2_DEVELOPMENT_PLAN.md` v1.2
> 默认排期：1 名全职开发者、每周 5 个有效开发日
> 目标分支：`codex/kline-v2`

## 1. 使用规则

- 主计划负责范围、架构、性能预算和功能编号；本文负责执行顺序、状态、依赖和时间窗口。
- 状态仅使用：`待开始`、`进行中`、`待提交`、`已完成`、`阻塞`。
- 开始任务前确认前置任务和 Definition of Ready；结束时补充提交、测试、性能或 Golden 证据。
- 同一时间最多一个关键路径任务处于 `进行中`；并行工作不得修改同一公共契约。
- 周期是规划窗口，不是无条件发布日期；法定节假日、设备或外部环境不可用时按实际调整并记录原因。

## 2. 审阅结论

### 2.1 可执行性

开发计划技术上可行，Phase 顺序已满足以下关键依赖：

```text
基线 → 架构契约 → 数据 Store → 指标/视口手势 → 分层渲染 → 币安核心体验
```

完整产品链路为：

```text
P0 → P1 → P2 → P3/P4 → P5 → P6 → P7 → P8 → P9
```

其中 `P3` 与 `P4` 只有在 `P1` 契约冻结且 `P2` 核心模型稳定后才能并行。单人开发时仍按 P3 后 P4 顺序执行，避免上下文切换。

### 2.3 暂未冻结的决策

以下问题必须在指定任务关闭，不能拖到 Renderer 迁移阶段临时决定：

| 决策 | 截止任务 | 默认建议 |
| --- | --- | --- |
| 新 Widget 使用 `KChart` 还是 `KChartWidget` | `P1-05` | 新 API 用 `KChart`，旧名称保留 facade |
| Controller 使用单快照还是多个 Listenable | `P1-02` | 对外只读总快照，内部按 StateSlice 细粒度通知 |
| 指标是否允许自定义 Renderer | `P3-01` | 允许注册 RendererDescriptor，但不暴露内部 Canvas 状态 |
| Web 文本测量和鼠标策略 | `P4-06` | 共享坐标内核，平台输入适配独立 |
| 旧 Renderer 的下线时间 | `P6-06` | 2.x 保留兼容 facade，后续主版本再删除 |

## 3. Definition of Ready / Done

### 3.1 Ready

任务进入开发前必须满足：

- 前置任务已完成或有明确、无风险的 mock/接口。
- 输入、输出、异常行为和兼容边界已写清楚。
- 需要的测试数据、设备和基线可用。
- 公共 API 变更已先更新草案或 ADR。
- 涉及性能时已有相同场景的对照基线。

### 3.2 Done

任务标记完成前必须满足：

- 实现与任务范围一致，没有夹带无编号功能。
- `dart format`、`flutter analyze` 和相关测试通过。
- 新增逻辑包含单测；视觉变化包含 Golden；手势包含 Widget/Integration 测试。
- 数据、指标或渲染变更附性能前后数据。
- 公共 API、README、CHANGELOG、迁移说明按影响更新。
- 主计划和本文状态同步，记录提交与验证证据。
