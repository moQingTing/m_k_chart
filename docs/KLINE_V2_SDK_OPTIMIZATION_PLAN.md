## 1. 目标与当前边界

本轮将已有 V2 内核整理为可直接接入、可扩展、可维护的 SDK，同时完成主图绘图的用户操作入口。
保留现有数据模型、指标算法、坐标变换和分层渲染基础，逐项迁移 Demo 的组装职责。

原 P0～P9-04 的完成记录代表当时范围内的交付。2026-10-22 起，`m_k_chart.dart` 从唯一正式入口
导出受控 V2 API；2.0.0 将该 API 集合纳入稳定兼容面。Profile/Web 和接入方反馈作为后续质量改进跟踪，
宿主网络及后台数据策略不属于核心库职责。

本轮不能仅因内部模块存在、Demo 能运行或原任务已勾选，就将新 SDK 接入和绘图 UI 标记完成。

## 2. 审查依据

以下是基线代码的静态检查结论；潜在缺陷需先复现，性能收益需测量，不将推断作为测试结果。

| 发现 | 代码依据 | 影响 |
| --- | --- | --- |
| V2 没有正式公开的完整 Widget/Controller 组合 | `lib/m_k_chart.dart`、`lib/v2_example_support.dart`、`docs/MIGRATING_TO_V2.md` | 宿主需要自行组装大量内部对象 |
| 副图移除后仍可能保留其选中面板 id | Demo 的 `_toggleSecondaryIndicator`、`_selectionFor`；`ChartLayoutModel.panel` 对未知 id 抛错 | 选中副图后关闭它或切换叠加布局可能异常 |
| 横向导航依靠槽位宽度相等推断 | Demo 的 `_handleChartIntent`；初始 `_itemExtent` 可为空 | 首次拖动、缩放边界处的取消选中语义不可靠 |
| 倒计时刷新触发页面级 setState | Demo 的 `_clockTimer` | 页面和快照组装产生额外工作；不等于所有图层必然重新录制 |
| 数据变更同时推进主题与布局版本 | Demo 的 `_applyDataWindow`、`_advanceRevision`、RenderSnapshot 组装 | 未变化的图层依赖也会失效 |
| 指标设置与图例仍包含名称判断和特例 | Demo 的 `_isIntegerParameter`、`_indicatorLegendLabel`、`_renderIndicatorSnapshot` | 新指标需要修改多处 UI 代码 |
| 批量指标失败未在 Demo 展示 | Demo 的 `_indicatorSnapshots` 仅消费 `batch.results` | 参数或计算失败时指标可能无提示消失 |
| Demo 过大且保留旧实现注释块 | Demo 3,614 行，约 400 行停用控件；测试也有停用块 | 接入阅读成本高，容易复制过时逻辑 |
| 数据更新或导航存在重复全量处理 | `ChartXTransform` 校验、`IndicatorDataChange.between`、`ChartCandleProjection.fromKlines` | 大数据和高频更新时有可测量的优化空间 |
| 主图绘图底层已有，Demo 尚未串联 | `lib/src/drawing/`、`ChartDrawingLayer`；Demo 未组装 anchoredDrawings | 需要补工具选择、创建、编辑、撤销和保存流程 |

## 3. 必须保持的行为

- 默认蜡烛图，保留主副图指标、配色、小数位、千分位和中文设置入口。
- 指标参数区域位于网格内部，背景透明，预留高度可配置且不被图形覆盖。
- 网格竖线与时间标签跟随数据移动，保留既有主副图横线与边界规则。
- 保持右侧虚拟留白、拖动最新 K 线至左侧、最新价箭头和返回最新的行为。
- 最新价倒计时按现有相邻 K 线时间间隔推导；无法推导时显示 `00:00`。
- 实时替换/追加不得随意取消选中；选中数据按序列身份和开盘时间恢复，避免索引漂移。
- 主动横向浏览清除点击选中态；缩放保留。数据被移除、面板被删除、交易对/周期切换时明确失效。
- 长按结束、鼠标悬浮离开与点击选中是不同交互，实施时分别定义并测试，避免一律持久化。
- 订单操作、绘图操作、十字线、平移缩放必须正确竞争手势；点击最新价箭头不打开信息面板。
- 旧公共入口继续兼容；不删除旧 API，不把内部实现全部导出充当正式 SDK。

### OPT-01：选中态边界

实施内容：

- 先建立“选中副图 → 关闭副图/切换叠加布局”的失败用例，再修复失效面板引用。
- 将导航来源明确建模，避免通过 `_itemExtent` 或浮点数相等猜测平移与缩放。
- 统一选中恢复策略，身份包含交易对、周期、价格来源、开盘时间及面板 id。
- 处理空数据、滚动窗口裁剪、选中 K 线移出可见区；是否隐藏或夹取视觉标签需明确并测试。

验收：首次拖动清除选中；缩放保留；替换/追加仍选中原 K 线；滚动窗口索引变化不串位；
关闭已选副图、移除全部副图和切换叠加布局无异常。主图与副图均需覆盖。

### OPT-02～OPT-04：正式接入能力

建议新组件使用 `KChart`，保留旧 `KChartWidget`；最终命名与签名在 OPT-02 的 API 草案/ADR 中冻结。

- Controller 负责数据替换、前插、追加、尾部更新、定位时间、返回最新、选中与绘图操作。
- 内部复用 KlineStore、实时合并策略、指标引擎和导航器，将一次数据变化作为原子事务处理。
- Widget 内部组装布局、渲染快照、手势、参数栏与信息面板，宿主无需自行创建 Painter。
- 支持主题、主副图配置、选中事件、历史加载请求、指标错误和绘图变化回调。
- 明确 Controller 的创建和销毁所有权；多图实例互不影响；Widget 更换 Controller 时正确解绑。
- 若支持受控数据输入与 Controller 命令两种模式，必须定义冲突规则与唯一数据所有者。
- 网络、密钥、账户、下单与存储介质继续由宿主负责。

验收：一个独立宿主可仅用正式公共入口创建 V2 图表并更新数据；不导入 `src`、Renderer 或
`v2_example_support.dart`；同时运行两个图表、切换数据源、销毁重建均无状态串扰。
导出变化按 API 策略同步 allowlist、草案、架构测试和迁移说明，不通过放宽测试绕过边界。

### OPT-05：状态通知与缓存失效

- 分离 data、indicatorConfig、viewport、selection、layout、theme、clock 等变化来源，明确映射到图层依赖。
- 倒计时与选中详情订阅各自状态；行情摘要和设置页不因每帧手势重建。
- 只有数据或计算参数变化才重新解析计算结果；图例与指标投射按相应依赖复用。
- 提取单一快照组装入口，避免基础快照与选中快照的配置字段漂移。
- 审核缓存键是否覆盖实际依赖，特别是换序列、修改指标参数、同版本号不同仓库的场景。

验收：以重建计数、图层录制次数、缓存统计证明倒计时不失效 K 线/网格层；仅选中变化不触发
指标重算；数据变更不伪装成主题变更；修改指标参数后量程和图例及时更新。

### OPT-06：指标扩展协议

- 指标元数据描述参数键、中文名称、数值类型、默认值、范围及关联校验。
- 描述序列名称格式、推荐样式、图例分组和可见序列；表达 SUPER 的单项趋势图例与 MA 的三线配置。
- 保持既有 definitionId/seriesId 兼容，新增注册能力不要求修改核心枚举或 Painter。
- 界面和引擎共享校验规则；隔离失败实例并向宿主暴露错误，不静默隐藏。

验收：新增一个自定义指标仅需提供定义/元数据并注册，即可进入设置页和图例；不同参数的同类
指标可同时显示；非法参数有明确反馈；一个指标失败不影响其他指标。

### OPT-07～OPT-08：示例、数据接入和生命周期

建议目录职责：

```text
example/lib/
  v2_chart_demo.dart       页面入口与工具按钮
  market/                 币安适配、历史请求、实时刷新
  settings/               行情、指标、图表、绘图设置面板
  examples/               最小接入、实时数据、自定义指标、绘图、配置恢复
```

- 提取可复用职责后删除已停用的旧控件块；旧测试逐项审计，迁移有效断言后清理。
- 不以文件行数作为唯一验收指标：示例必须让读者看清输入、事件和释放流程。
- 行情源可注入，提供确定性模拟源；测试不依赖公网，也不通过私有 State 调用驱动更新。
- 统一请求代际、异常、取消/过期结果处理和轮询不重入策略。
- Example 可处理后台、路由不可见、恢复前台与销毁的刷新生命周期；该数据源策略由宿主负责，不作为核心库发布门槛。
- 高频推送允许按帧批量提交，但不能丢失跨周期新 K 线、闭合事件或必要的顺序信息。
- 保留现有 REST 演示；注入协议支持宿主 WebSocket，不强制在本轮新增交易所网络依赖。
- 中文注释重点覆盖契约、单位、异常和扩展步骤；示例说明与正式迁移指南保持一致。

验收：最小示例可独立运行；模拟源覆盖替换、追加、乱序和切换；后台刷新按策略暂停，销毁后
无通知；旧请求不能覆盖新交易对；现有设置和图表外观不退化。

### OPT-09～OPT-10：主图绘图

沿用现有模型、渲染和命令历史，补齐用户可操作的闭环：

- 工具按钮打开面板，选择趋势线、水平线、垂直线、射线、矩形、平行通道、斐波那契回撤、文本和价格标记。
- 每类工具明确所需锚点数；依次落点、预览、完成或取消，限制在主图内创建。
- 支持命中选中、控制点调整、整体移动、OHLC 磁吸、锁定、删除、显示/隐藏及撤销/重做。
- 明确绘图模式与浏览模式；处理双指缩放、父级滚动、订单拖动、十字线之间的优先级。
- 拖动预览可高频更新，但一次完整拖动只形成一条可撤销命令；取消还原原状态。
- 绘图持久化使用时间/价格锚点和版本化 JSON；存储由宿主通过回调完成。
- 切换交易对和价格来源隔离绘图；切换周期配置为保留/隐藏，复用已有坐标恢复协议。
- 历史范围外锚点、未来空白区落点需明确策略；当前时间变换会夹取到首尾数据，不能据此宣称
  已支持无限未来绘图。扩展外推时需要单独定义周期、缺失数据和月线的时间规则。

验收：所有工具完成创建和编辑；缩放/拖动/加载历史后保持锚定；实时更新不丢草稿；撤销/重做
恢复正确；序列化往返、旧版本迁移、跨周期/交易对切换与手势竞争有自动化证据。

### OPT-11：有证据的性能优化

先测量 OPT-05/08 后的实现，再选择实际热点：

- 每个不可变数据版本只验证一次有序性；外部未知输入仍须校验。
- 数据仓库提供可信变化范围，多个指标复用一次变化识别；自定义输入保留结构比较回退。
- 普通蜡烛采用可见区或低分配投射；Heikin-Ashi 等递归模式保留正确的历史依赖。
- 按需优化列表复制与缓存驻留，不因追求 O(1) 破坏快照不可变性。

基准矩阵：100/2,000/10,000 根，2/6 个指标，尾部替换、追加、滚动窗口、历史前插、拖动、
缩放和选中；加入 10 Hz 数据更新。记录输入处理、指标计算、UI/Raster 的 P50/P95/P99、
分配与内存、缓存命中和图层录制次数。Host benchmark 串行执行；设备、模式、采样和预热一致。

验收：与原性能预算及本轮同条件基线比较；全量/增量结果一致；关键场景无回退。
没有设备测量时明确标记未验证，不能以 Debug Host 耗时替代真机帧率结论。

## 5. 执行顺序与完成标准

按任务依赖实施，默认顺序：OPT-01 → OPT-02～04 → OPT-05～08 → OPT-09～10 → OPT-11 → OPT-12。
每次完成可独立验证的一项或一组关联任务，再推进下一项，避免同时修改算法、手势和公开接口。

每项任务的完成记录必须包含：实际修改、关联提交、执行的测试与结果、必要的性能/视觉证据、
遗留问题。文档更新不等于功能实现；没有执行的真机、网络或发布验证必须明确保留为未完成。
